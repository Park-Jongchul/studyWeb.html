코드를 배우기 전에: 다운로드·설치·실행은 서로 달라요.

다운로드는 인터넷의 파일을 내 컴퓨터로 받는 일, 설치는 그 프로그램을 사용할 준비를 하는 일, 실행은 준비된 프로그램을 여는 일이에요. 다운로드 버튼을 한 번 눌렀다고 설치가 끝난 것은 아닙니다. 이 교재는 키보드와 마우스가 있는 Windows PC 또는 Mac을 기준으로 합니다. 휴대전화만으로 진행하는 수업은 아니에요.

교재 ZIP은 먼저 풀어 주세요. Windows: 다운로드 폴더에서 ZIP 우클릭 → 모두 압축 풀기 → 추출. Mac: Finder의 다운로드에서 ZIP을 두 번 클릭. 생긴 폴더의 index.html을 두 번 눌러 교재를 엽니다. ZIP 미리보기 안에서 예제 파일을 수정하지 마세요.

클릭은 마우스 왼쪽 버튼 한 번, 더블클릭은 빠르게 두 번, 우클릭은 오른쪽 버튼으로 메뉴를 여는 일입니다. Mac 트랙패드는 두 손가락 클릭으로 우클릭할 수 있어요. 주소창은 브라우저 맨 위에 사이트 주소를 쓰는 긴 칸입니다. 아래 공식 링크를 누르면 주소를 직접 입력하지 않아도 돼요.

앱 개발에는 어떤 도구를 쓰나요?

Android Studio는 Android 앱을 만드는 무료 개발 프로그램입니다. 글을 적는 편집기, 화면을 보는 도구, 오류 검사, 앱 조립 도구를 한 창에 모아 놓은 통합 개발 환경(IDE)이에요. 웹 수업의 VS Code 대신 이 프로그램에서 앱 프로젝트를 엽니다. 이 교재에서 만드는 앱은 Android용이며 iPhone에서는 설치·실행할 수 없습니다.

다운로드 전에 컴퓨터를 확인해요.

공식 설치 안내와 현재 시스템 요구사항를 먼저 여세요. 가상 휴대전화는 메모리·디스크를 많이 사용하며 Studio만 실행하는 조건과 Emulator까지 실행하는 조건이 다릅니다. Windows는 설정 → 시스템 → 정보에서 OS·RAM·CPU를, Mac은 사과 메뉴 → 이 Mac에 관하여에서 칩·메모리를 확인합니다. 현재 공식 지원 OS·CPU 조건에 맞지 않으면 설치 파일을 임의로 고르지 말고 교수자와 확인하세요.

설치 파일을 받은 뒤에도 SDK·가상 기기 이미지를 추가로 받으므로 인터넷 연결과 여유 저장 공간이 필요합니다. 첫 수업은 다운로드와 설치만으로 길어질 수 있어요. Studio에 필요한 Java 실행 환경과 Kotlin 지원은 함께 제공되므로 이 과정에서 별도로 Java나 Kotlin 설치 파일을 찾지 않아도 됩니다.

Android Studio 공식 다운로드 페이지 열기 →. 자동 선택이 맞지 않으면 페이지 아래 Android Studio downloads 표에서 OS·CPU를 확인하세요. Mac 칩은 사과 메뉴 → 이 Mac에 관하여에서 확인합니다. Apple M…은 Apple silicon이며 Intel 표시는 Intel용입니다. 버전 이름과 파일 크기는 바뀔 수 있어요.

설치가 끝났는지 어떻게 알 수 있나요?

다운로드 완료 표시만으로는 부족합니다. ① Studio를 다시 열 수 있고 ② SDK 구성 요소 다운로드가 끝났고 ③ Welcome의 New Project가 보이는지 확인하세요. AI·Google 계정 로그인 제안은 이 로컬 실습의 필수 단계가 아닙니다. 설정창 이름이나 순서가 버전에 따라 일부 달라도 SDK 설치 완료를 확인하고 진행합니다.

SDK 다운로드가 실패하면 오류 문장을 확인하고 인터넷 연결·저장 공간을 점검한 뒤 Retry를 누르세요. Welcome → More Actions → SDK Manager(프로젝트 안에서는 Tools → SDK Manager)에서 SDK Platforms와 SDK Tools 상태를 확인할 수 있습니다. 처음부터 파일을 지우거나 Gradle 버전을 무작정 바꾸지 마세요. SDK Manager에서 필요한 API의 체크가 비어 있다면 선택 → Apply → 라이선스 확인 → 다운로드 완료 순서로 설치합니다.

이제 아래의 프로젝트 만들기로 이동합니다. Studio 설치 → 프로젝트 생성 → Gradle 준비 → 실행 기기 준비 → Run으로 빌드·설치·실행은 서로 다른 단계입니다. 아직 휴대전화 화면에 앱이 나오지 않는 것이 정상이에요.

프로젝트를 만든다는 것은 앱의 작업 폴더와 준비 파일을 함께 만드는 일이에요.

앱 하나에는 화면 XML, 동작 Kotlin, 이미지, 앱 설정, 조립 설정이 함께 들어갑니다. 이 파일들이 서로 연결된 묶음이 프로젝트예요. Studio의 New Project는 필요한 폴더와 준비 파일을 처음부터 만들어 줍니다.

템플릿은 처음부터 빈 종이에 그리지 않도록 주는 출발 양식이에요. 이 책은 XML을 먼저 배우므로 Empty Views Activity를 고릅니다. 비슷한 이름인 Empty Activity는 다른 화면 방식의 출발점이므로 이름 끝까지 읽으세요. 아래 그림은 설치를 끝내고 Studio를 실행한 뒤의 순서입니다.

Gradle Sync는 이 프로젝트가 어떤 도구·라이브러리를 사용하는지 읽고 Studio와 설정을 맞추는 준비 작업이에요. 필요한 부품을 인터넷에서 받기도 합니다. 프로젝트를 만들었다는 것과 앱 조립이 끝났다는 것은 달라요.

아래쪽 진행 표시가 끝날 때까지 기다립니다. 첫 실행은 다운로드 때문에 오래 걸릴 수 있어요. 빨간 메시지가 남으면 Build 창의 Sync 항목을 눌러 첫 원인을 봅니다. 버전 숫자를 아무렇게나 바꾸기보다 네트워크와 설치된 SDK부터 확인해요.

빌드·설치·실행은 서로 다른 일이에요.

빌드(build)는 Kotlin과 XML·이미지를 모아 안드로이드가 설치할 수 있는 앱으로 조립하는 과정입니다. Kotlin 문법 검사와 변환, 리소스 검사, 포장 같은 작업이 포함됩니다. 이 과정에서 잘못된 괄호나 없는 자원 이름을 발견하면 빌드가 멈춰요.

설치는 조립된 앱을 기기에 넣는 일이고, 실행은 그 앱을 시작하는 일이에요. Studio의 Run은 필요한 빌드부터 설치·실행까지 이어서 해 줍니다. 초보 실습에서는 아래 Run 순서 하나로 진행해도 충분해요.

package com.example.beautystart

import android.os.Bundle
import android.view.View
import android.widget.*
import androidx.appcompat.app.AppCompatActivity
import androidx.activity.enableEdgeToEdge
import androidx.core.view.ViewCompat
import androidx.core.view.WindowInsetsCompat

class MainActivity : AppCompatActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        enableEdgeToEdge()
        setContentView(R.layout.activity_main)

        // 상태 표시줄과 본문이 겹치지 않게 하는 준비 코드예요.
        ViewCompat.setOnApplyWindowInsetsListener(findViewById<View>(R.id.mainRoot)) { view, insets ->
            val bars = insets.getInsets(WindowInsetsCompat.Type.systemBars())
            view.setPadding(bars.left, bars.top, bars.right, bars.bottom)
            insets
        }
    }
}

실습 시작 위치와 완료 확인

어디서 시작하나요? 2장의 실행되는 XML을 백업하고 여세요.

무엇을 하고 확인하나요? XML 전체 예제인지 속성 한 줄인지 구별합니다. 속성은 해당 태그의 > 앞에 넣고 id가 중복되지 않는지 확인 → Run → 글자·버튼 변화 확인.

부품 이름과 속성 이름을 차례대로 읽어요

TextView는 글자 부품, Button은 버튼 부품, LinearLayout은 다른 부품을 담는 상자예요. 태그 이름이 어떤 객체를 만들지 정하고 그 안의 속성은 그 객체의 초기 모양을 정합니다.

android:layout_width="match_parent"에서 속성 이름은 layout_width, 설정 값은 match_parent입니다. 이 값은 부모가 허용한 너비를 사용한다는 뜻이에요. wrap_content는 내용과 부품의 최소 크기에 맞추며 무조건 0이 되는 것은 아닙니다.

XML 태그는 어떤 화면 부품인지 표시해요. <TextView … />는 글자 부품 하나예요. 속성은 태그 안에 쓰는 설정이고, 값은 따옴표 안에 들어가요. 태그 이름을 보고 부품을 구별하고, 속성 이름을 보고 무엇을 바꾸는지 읽어 보세요.

실제 조각이름뜻
<Button … />태그버튼 부품 하나. />로 닫는 단독 태그예요.
android:text="찜하기"속성 = 값이 부품의 표시 글자를 찜하기로 설정해요.
android:id="@+id/likeButton"고유 이름 만들기나중에 Kotlin이 이 버튼을 찾을 때 사용할 이름이에요. 같은 화면에서 중복하지 않아요.
android:layout_width="match_parent"너비부모 상자가 허용하는 너비를 채워요.
android:layout_height="wrap_content"높이내용에 필요한 만큼 높이를 잡아요.
xmlns:android="…"이름 공간android:로 시작하는 속성이 안드로이드 설정임을 알려 줘요. 루트 태그에 한 번 선언해요.

이 장을 마치면

실습 시작 위치와 완료 확인

어디서 시작하나요? activity_main.xml의 최상위 레이아웃부터 찾으세요.

무엇을 하고 확인하나요? ScrollView는 바로 아래 자식을 하나만 갖습니다. 여러 요소는 그 안의 LinearLayout에 넣어요. dp는 크기·간격, sp는 글자 크기입니다. 저장 → Run → 화면 끝까지 스크롤 확인.

부모 상자 안에 자식 부품이 들어가요

서랍 안에 작은 정리함을 넣듯, 세로 상자 안에 가로 상자를 넣을 수 있어요. 가장 바깥 부품 하나를 루트라고 하고 안으로 들여쓴 부품을 자식이라고 부릅니다. 화면의 포함 관계를 종이에 먼저 그려 보세요.

dp는 기기 화면 밀도를 고려하는 길이 단위이고, sp는 글자 크기 설정도 고려하는 글자 단위예요. 24dp 여백과 24sp 글자는 서로 다른 설정입니다. 안쪽 padding과 바깥 layout_margin도 위치가 달라요.

부품을 세로로 쌓는 상자 안에 가로 상자를 넣으면 작은 화면도 만들 수 있어요. 부모는 나를 감싸는 상자, 자식은 그 안의 부품입니다. 들여쓰기는 이 포함 관계를 보기 쉽게 해 줍니다.

ScrollView: 화면보다 길면 스크롤세로 LinearLayout: 위→아래가로 LinearLayout: 왼쪽→오른쪽

이 예제 XML 파일 · 짝이 되는 Kotlin 준비 파일. 두 파일은 같은 예제끼리 사용해요. 다운로드한 ZIP의 같은 이름 폴더에도 들어 있어요.

새 파일을 만드는 버튼까지 따라가요.

왼쪽 프로젝트 창에서 Android 보기의 app → res를 펼치세요. layout 안의 activity_main.xml은 이미 있습니다. 코드 파일을 찾을 때는 app → kotlin+java(버전에 따라 java) → 내 패키지 → MainActivity를 엽니다. XML 편집 화면 오른쪽 위 Code/Split을 누르면 글로 된 XML을 적을 수 있어요.

문자·색은 res → values → strings.xml 또는 colors.xml을 엽니다. 이미 <resources>가 있으면 그 안에 새 <string>·<color> 항목을 추가하세요. resources 문서를 두 겹으로 넣거나 기존 테마에 필요한 색을 통째로 지우지 않습니다. 파일이 없다면 values 우클릭 → New → Values Resource File → 파일 이름 strings 또는 colors → OK.

그림 XML은 drawable 우클릭 → New → Drawable Resource File → 파일 이름(예: beauty_placeholder) → OK → 생성된 내용을 예제의 <vector> 전체로 교체합니다. PNG/JPG는 컴퓨터의 파일을 drawable로 복사·붙여넣기하고 확인창을 완료합니다. 이름은 소문자 영문·숫자·밑줄로 쓰고 공백·하이픈은 피하세요. beauty_photo.png는 @drawable/beauty_photo로 참조합니다.

폴더가 없다면 res 우클릭 → New → Android Resource Directory → Resource type을 drawable 또는 layout으로 선택 → OK. 오류가 생기면 파일명과 참조 이름부터 맞추고 저장 → Run합니다.

실습 시작 위치와 완료 확인

어디서 시작하나요? app → res에서 layout·values·drawable 폴더 위치를 확인하세요.

무엇을 하고 확인하나요? 리소스 추가 방법은 아래 절차를 먼저 읽으세요. @string/이름과 실제 string name, @drawable/이름과 파일명을 맞추고 Run. 빨간 참조 오류가 있으면 이름·대소문자부터 확인합니다.

같은 문구를 한 곳에서 관리하면 바꾸기 쉬워요

세 화면에 스튜디오 이름을 각각 적으면 이름을 바꿀 때 세 곳을 고쳐야 합니다. 문자열 자원으로 한 곳에 모으고 이름으로 참조하면 관리가 쉬워요. 그림과 색도 별도 자원으로 둘 수 있습니다.

@string/studio_title에서 @string은 자원의 종류, studio_title은 내가 정의한 이름입니다. 실제 표시 글자는 strings.xml에 있어요. @drawable/style_sample은 그림 자원 이름이며 파일 확장자는 참조에 쓰지 않아요.

자주 바꾸는 글자·색·그림은 리소스로 따로 모아 둘 수 있어요. XML의 @string/이름은 문자열 자원, @color/이름은 색 자원, @drawable/이름은 그림 자원을 가져온다는 뜻입니다. @는 “다른 자원을 참조해”라고 읽어 보세요.

  1. res/values/strings.xml에 아래 문자열 항목을 추가해요. app_name은 기존 항목이 있으면 한 번만 둡니다.
  2. res/values/colors.xml이 없으면 Values Resource File로 만들고 아래 색 항목을 추가해요. 기존 테마에서 쓰는 색 항목은 지우지 않아요.
  3. res/drawable에 style_sample.xml 파일을 만들고 제공된 벡터 그림을 넣어요. 이 그림은 교재용으로 만든 단순 실루엣입니다.
  4. activity_main.xml을 아래 파일로 바꾸고 실행해요. 실제 사진을 쓰려면 영문 소문자·숫자·밑줄로 된 파일명을 사용해요.

XML로 모양을 만든 다음, Kotlin으로 할 일을 적어요

버튼이 보인다는 것과 버튼을 눌러 일이 일어난다는 것은 다릅니다. XML은 부품을 만들었고, Kotlin은 눌렀을 때 변수·조건·함수를 사용해 무엇을 할지 적습니다.

7장. 변수와 자료형: 이름·가격·참과 거짓

이 장을 마치면

val·var·숫자·문자열·불리언을 구별하고 값을 추적해요.

실습 시작 위치와 완료 확인

어디서 시작하나요? Kotlin Playground에서 독립 fun main 예제를 실행하세요.

무엇을 하고 확인하나요? fun main이 두 개 생기지 않게 편집 영역 전체를 교체합니다. var는 재대입 가능, val은 같은 이름에 새 값 재대입 불가입니다. 값 하나만 바꾸고 Run해 출력 비교.

변수 이름과 값은 서로 다른 것이에요.

예약 가능 인원이 3명이라고 해 봅시다. 3은 계산할 숫자 값이고, 그 숫자가 무엇을 의미하는지 알려 주는 이름을 remaining이라고 붙일 수 있어요. 영어로 남은 수라는 뜻입니다. 컴퓨터가 영어 뜻을 해석해서 동작하는 것은 아니고, 우리가 읽기 좋은 이름을 고른 거예요.

var remaining = 3을 “변경 가능한 이름 remaining을 처음 만들고 숫자 3을 연결한다”라고 읽어 보세요. 이름을 처음 만드는 일을 선언, 값을 연결하는 일을 대입이라고 합니다. 이 한 줄에서는 두 일을 함께 해요.

코드에서 remaining을 따옴표 없이 쓰면 현재 연결된 값을 읽습니다. "remaining"처럼 따옴표로 감싸면 변수 이름을 읽는 명령이 아니라 r·e·m…이라는 글자 값이 됩니다. 이 차이를 직접 출력해서 확인할 수 있어요.

어디서 시작하나요? Playground에 함수 정의와 main 호출을 함께 넣으세요.

11장. 객체와 클래스: 코드에서 직접 알아보기

이 장을 마치면

실습 시작 위치와 완료 확인

어디서 시작하나요? Playground에서 클래스와 main이 함께 있는 예제를 실행하세요.

무엇을 하고 확인하나요? 클래스 정의만으로 물건 한 개가 생기는 것은 아닙니다. 생성 호출로 두 인스턴스를 만들고 각각의 값이 다른지 봅니다. Android의 MainActivity는 이후 Studio에서 다룹니다.

먼저 한 서비스의 정보를 한 덩어리로 묶어요.

“내추럴 커트”라는 이름, 30000이라는 가격, 40이라는 소요 시간은 같은 서비스의 정보입니다. 따로 떨어뜨려 두면 어떤 가격이 어떤 서비스에 속하는지 헷갈릴 수 있어요. 관련 정보를 하나로 묶은 값이 객체입니다.

같은 항목을 가진 서비스를 여러 개 만들고 싶으면 그 객체의 항목과 동작을 정하는 규칙이 필요해요. 그 규칙을 정의하는 것이 클래스입니다. 클래스는 “커트 한 건”이 아니라 “서비스 한 건에는 어떤 정보가 있어야 하는가”를 설명합니다.

클래스로 만든 커트 객체와 펌 객체는 각각 다른 실제 데이터입니다. 인스턴스는 이처럼 클래스로 만든 개별 객체를 가리키는 말이에요. 여러 단어가 나와도 “정의한 규칙”과 “실제로 만든 값”을 구별하면 출발할 수 있어요.

내가 묻는 질문코드에서 찾는 것
어떤 규칙으로 만들까?class Service … — 클래스 정의
그 규칙으로 하나 만들어 볼까?Service(…) 또는 new Service(…) — 객체 생성
만든 것을 어떤 이름으로 읽을까?cut — 변수 이름
그 객체의 가격은?cut.price — 속성 읽기
그 객체에게 안내 문장을 만들게 할까?cut.label() — 메서드 호출

함수·속성·메서드도 역할로 구별해요.

속성은 객체 안에 붙여 둔 정보이고 메서드는 객체에 속한 함수예요. cut.price에는 괄호가 없으므로 현재 정보를 읽습니다. cut.label()에는 괄호가 있으므로 그 객체에 속한 절차를 호출합니다. 점(.)은 그 객체의 항목으로 들어간다고 읽어 보세요.

클래스 이름과 변수 이름은 내가 정합니다. 클래스는 Service처럼 대문자로 시작하고 변수·함수는 cut·showLabel처럼 소문자로 시작하는 관례를 사용하면 구분이 쉬워요. 다만 대문자라는 이유만으로 클래스라고 판단하지 말고 class 정의와 생성 위치를 확인하세요.

서비스 한 건에는 이름, 가격, 소요 시간이 함께 있어요. 이것을 각각 따로 관리하면 서로 뒤섞일 수 있어요. 객체는 관련 정보와 동작을 한 덩어리로 다루는 값입니다. 속성은 그 안의 데이터, 메서드는 그 안에 속한 함수예요. 클래스는 이런 객체를 만드는 규칙을 이름 붙여 정의한 것입니다. 클래스로 만든 개별 객체를 인스턴스라고도 불러요.

람다·이름 없는 함수는 왜 갑자기 나오나요?

먼저 “함수는 어떤 일을 실행할 절차”였다는 것을 떠올려 보세요. 이제 그 절차를 값처럼 변수에 넣거나 다른 함수에 전달하고 싶습니다. 예를 들어 “이 버튼을 눌렀을 때 할 일”을 버튼에게 건네줄 수 있어요. 이때 짧은 절차에 매번 새 이름을 만들지 않고 함수 자체를 적는 문법이 필요합니다.

Kotlin에서는 이렇게 이름 없이 적는 함수 표현을 람다라고 부릅니다. 중괄호가 있다는 이유만으로 모두 람다는 아니에요. class나 if의 중괄호와 구별해서, 함수 값으로 사용하고 있는지 문맥을 봐야 합니다.

중요한 것은 짧게 쓰는 기술이 아니라 실행할 절차 자체와 그 절차를 실행한 결과의 구별이에요. 실제로 괄호를 붙여 호출하는 순간에 실행됩니다. 람다를 썼다고 무조건 나중에 실행되는 것은 아니고, 받은 쪽이 언제 호출하느냐에 따라 달라져요.

먼저 예상하세요. 실행 전 아래 코드를 읽고 결과를 종이에 한 줄 써 보세요.

package com.example.beautystart

import android.os.Bundle
import android.view.View
import android.widget.*
import androidx.appcompat.app.AppCompatActivity
import androidx.activity.enableEdgeToEdge
import androidx.core.view.ViewCompat
import androidx.core.view.WindowInsetsCompat

class MainActivity : AppCompatActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        enableEdgeToEdge()
        setContentView(R.layout.activity_main)

        // 상태 표시줄과 본문이 겹치지 않게 하는 준비 코드예요.
        ViewCompat.setOnApplyWindowInsetsListener(findViewById<View>(R.id.mainRoot)) { view, insets ->
            val bars = insets.getInsets(WindowInsetsCompat.Type.systemBars())
            view.setPadding(bars.left, bars.top, bars.right, bars.bottom)
            insets
        }
        val statusText = findViewById<TextView>(R.id.statusText)
        val likeButton = findViewById<Button>(R.id.likeButton)
        var liked = false

        likeButton.setOnClickListener {
            liked = !liked
            if (liked) {
                statusText.text = "찜한 스타일이에요."
                likeButton.text = "찜 해제"
            } else {
                statusText.text = "아직 찜하지 않았어요"
                likeButton.text = "찜하기"
            }
        }
    }
}

import android.os.Bundle
import android.view.View
import android.widget.*
import androidx.appcompat.app.AppCompatActivity
import androidx.activity.enableEdgeToEdge
import androidx.core.view.ViewCompat
import androidx.core.view.WindowInsetsCompat

class MainActivity : AppCompatActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        enableEdgeToEdge()
        setContentView(R.layout.activity_main)

        // 상태 표시줄과 본문이 겹치지 않게 하는 준비 코드예요.

            insets

        val priceInput = findViewById<EditText>(R.id.priceInput)

                nameInput.error = "스타일 이름을 적어 주세요."

            resultText.text = "화면에만 추가했어요. 다시 실행하면 사라져요."
            nameInput.text.clear()
            priceInput.text.clear()

package com.example.beautystart

import android.os.Bundle
import android.view.View
import android.widget.*
import androidx.appcompat.app.AppCompatActivity
import androidx.activity.enableEdgeToEdge
import androidx.core.view.ViewCompat
import androidx.core.view.WindowInsetsCompat

class MainActivity : AppCompatActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        enableEdgeToEdge()
        setContentView(R.layout.activity_main)

        // 상태 표시줄과 본문이 겹치지 않게 하는 준비 코드예요.
        ViewCompat.setOnApplyWindowInsetsListener(findViewById<View>(R.id.mainRoot)) { view, insets ->
            val bars = insets.getInsets(WindowInsetsCompat.Type.systemBars())
            view.setPadding(bars.left, bars.top, bars.right, bars.bottom)
            insets
        }
        val statusText = findViewById<TextView>(R.id.statusText)
        val likeButton = findViewById<Button>(R.id.likeButton)
        val resetButton = findViewById<Button>(R.id.resetButton)
        val prefs = getSharedPreferences("beauty_practice", MODE_PRIVATE)
        var liked = prefs.getBoolean("liked_cut", false)

        fun showStatus() {
            statusText.text = if (liked) "찜한 스타일이에요." else "아직 찜하지 않았어요"
            likeButton.text = if (liked) "찜 해제" else "찜하기"
        }
        showStatus()
        likeButton.setOnClickListener {
            liked = !liked
            prefs.edit().putBoolean("liked_cut", liked).apply()
            showStatus()
        }
        resetButton.setOnClickListener {
            prefs.edit().remove("liked_cut").apply()
            liked = false
            showStatus()
        }
    }
}

package com.example.beautystart

import android.os.Bundle
import android.view.View
import android.widget.*
import androidx.appcompat.app.AppCompatActivity
import androidx.activity.enableEdgeToEdge
import androidx.core.view.ViewCompat
import androidx.core.view.WindowInsetsCompat

class MainActivity : AppCompatActivity() {
    data class Style(val id: Int, val name: String, val category: String, val price: Int)
    private val styles = listOf(
        Style(1, "내추럴 커트", "헤어", 30000),
        Style(2, "웨이브 펌", "헤어", 70000),
        Style(3, "데일리 메이크업", "메이크업", 50000)
    )

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        enableEdgeToEdge()
        setContentView(R.layout.activity_main)

        // 상태 표시줄과 본문이 겹치지 않게 하는 준비 코드예요.
        ViewCompat.setOnApplyWindowInsetsListener(findViewById<View>(R.id.mainRoot)) { view, insets ->
            val bars = insets.getInsets(WindowInsetsCompat.Type.systemBars())
            view.setPadding(bars.left, bars.top, bars.right, bars.bottom)
            insets
        }
        val searchInput = findViewById<EditText>(R.id.searchInput)
        val searchButton = findViewById<Button>(R.id.searchButton)
        val onlyLiked = findViewById<CheckBox>(R.id.onlyLiked)
        val statusText = findViewById<TextView>(R.id.statusText)
        val styleList = findViewById<LinearLayout>(R.id.styleList)
        val detailText = findViewById<TextView>(R.id.detailText)
        val resetButton = findViewById<Button>(R.id.resetButton)
        val prefs = getSharedPreferences("beauty_lookbook", MODE_PRIVATE)

        // 읽어 온 Set을 직접 바꾸지 않고, 수정 가능한 복사본을 만들어요.
        val likedIds = (prefs.getStringSet("liked_ids", emptySet()) ?: emptySet()).toMutableSet()
        if (savedInstanceState != null) {
            searchInput.setText(savedInstanceState.getString("query", ""))
            onlyLiked.isChecked = savedInstanceState.getBoolean("only_liked", false)
            detailText.text = savedInstanceState.getString("detail", "스타일을 선택하세요.")
        }

        fun renderStyles() {
            styleList.removeAllViews()
            val query = searchInput.text.toString().trim()
            val visible = styles.filter { style ->
                style.name.contains(query, ignoreCase = true) &&
                    (!onlyLiked.isChecked || style.id.toString() in likedIds)
            }
            statusText.text = if (visible.isEmpty()) {
                "조건에 맞는 스타일이 없어요."
            } else {
                "${visible.size}개 표시 · 찜 ${likedIds.size}개"
            }
            for (style in visible) {
                val card = LinearLayout(this)
                card.orientation = LinearLayout.VERTICAL
                val space = (12 * resources.displayMetrics.density).toInt()
                card.setPadding(space, space, space, space)

                val title = TextView(this)
                title.text = "${style.name} · ${style.category} · ${style.price}원"
                title.textSize = 20f

                val detailButton = Button(this)
                detailButton.text = "${style.name} 자세히 보기"
                detailButton.setOnClickListener {
                    detailText.text = "선택: ${style.name} / ${style.category} / ${style.price}원"
                }
                val likeButton = Button(this)
                val key = style.id.toString()
                likeButton.text = if (key in likedIds) "${style.name} 찜 해제" else "${style.name} 찜하기"
                likeButton.setOnClickListener {
                    if (key in likedIds) likedIds.remove(key) else likedIds.add(key)
                    prefs.edit().putStringSet("liked_ids", likedIds.toSet()).apply()
                    renderStyles()
                    // 목록 재생성 뒤 키보드·보조기기 탐색을 위한 고정 위치예요.
                    searchButton.requestFocus()
                }
                card.addView(title)
                card.addView(detailButton)
                card.addView(likeButton)
                styleList.addView(card)
            }
        }
        searchButton.setOnClickListener { renderStyles() }
        onlyLiked.setOnCheckedChangeListener { _, _ -> renderStyles() }
        resetButton.setOnClickListener {
            likedIds.clear()
            prefs.edit().remove("liked_ids").apply()
            searchInput.setText("")
            onlyLiked.isChecked = false
            detailText.text = "스타일의 자세히 보기를 눌러 주세요."
            renderStyles()
        }
        renderStyles()
    }

    override fun onSaveInstanceState(outState: Bundle) {
        outState.putString("query", findViewById<EditText>(R.id.searchInput).text.toString())
        outState.putBoolean("only_liked", findViewById<CheckBox>(R.id.onlyLiked).isChecked)
        outState.putString("detail", findViewById<TextView>(R.id.detailText).text.toString())
        super.onSaveInstanceState(outState)
    }
}
