두 사람의 첫 코딩 수업

상담 웹과 뷰티 앱을 목표로 하는 기본 20회 + 웹 공개 4회 · 교수자 가이드

완전 처음인 성인 학습자오프라인 열람 · 인쇄 가능

오늘은 한 가지를 바꾸면 충분해요.

코드는 컴퓨터가 할 일을 적은 글입니다. 처음부터 긴 코드를 외울 필요는 없어요. 결과를 예상하고 → 실행하고 → 한 줄을 바꾸고 → 달라진 이유를 말하는 것이 이 책의 공부 방법이에요. 처음에는 복사해도 괜찮아요. 두 번째에는 한 줄을 직접 바꾸고, 세 번째에는 책을 덮고 짧은 예제를 다시 써 보세요.

① 예상하기② 실행하기③ 바꿔 보기④ 내 말로 설명하기

각 예제는 독립적으로 실행합니다. 앞 예제의 변수를 다음 예제에서 자동으로 가져오지 않습니다. ‘일부 교체’라고 쓴 앱 코드는 지정한 위치에만 넣으세요. 오류는 실력 평가가 아니라 컴퓨터가 알려 주는 수정 위치예요.

책 속 이름과 가격은 가상입니다. 상담 웹은 소개와 예약 희망 시간 연습, 뷰티 앱은 스타일 목록과 찜 기능까지 만듭니다. 실제 예약 전송·확정, 결제, 상담 기록 관리 기능은 이 기초 과정의 다음 단계입니다.

장 완료 표시는 현재 브라우저에만 저장됩니다. 브라우저 설정에 따라 저장되지 않을 수 있어요. 본문·코드·도형은 인터넷 없이 볼 수 있고, 외부 참고 링크와 Kotlin 온라인 실행에는 인터넷이 필요합니다.

LESSON 01

1장. 두 사람을 위한 수업 설계

이 장을 마치면

각자의 목표·언어·학습 범위와 시간 가정을 정해요.

처음부터 아는 단어로 설명하고 실제 코드에 연결해요.

처음 만나는 단어를 한 문장으로 정의하고 바로 긴 코드로 넘어가지 않습니다. “무슨 일에 쓰는가 → 가장 작은 예 → 실행 순서 → 한 줄 변경 → 내 말로 설명”의 다섯 단계를 반복합니다.

웹은 파일·HTML·CSS를 먼저 경험하고, 앱은 XML 화면부터 시작합니다. 두 사람 모두 눈에 보이는 화면을 바꾼 뒤 동작에 필요한 언어 기초를 배우게 했어요.

트랙새 학습 순서
상담 웹1~4장 파일·HTML·CSS·배치 → 5~11장 JavaScript 기초 → 12~16장 함수 전달·이벤트·입력·프로젝트 → 17~20장 호스팅·도메인·수정 배포
뷰티 앱1~5장 XML 화면 → 6~11장 Kotlin 기초 → 12장 람다·이벤트 → 13~16장 입력·복원·저장·최종 앱
기간기본 20회 + 웹 공개 실습 4회. 회당 120분과 주 2시간 복습. 함수·람다는 필요하면 각각 한 회 더 배정.
공통 목표입력과 결과를 구분하고 작은 변경을 혼자 할 수 있음. 정의·호출·저장·실행을 구별해 설명할 수 있음.

LESSON 03

3장. 한 번의 과외를 진행하는 방법

이 장을 마치면

설명·예측·실행·수정·회고를 120분에 배분해요.

시간무엇을 하나요?선생님이 할 말 / 확인
0~10분지난 내용 꺼내기지난주 변수의 현재 값은? 함수는 정의만 하면 실행될까?
10~25분새 개념 한 개와 비유비유 뒤에 실제 코드의 기호를 짚어요. class, fun/function, =를 직접 찾게 해요.
25~45분작은 예제 따라 하기먼저 결과를 종이에 쓰고 실행해요. 선생님이 키보드를 대신 치지 않아요.
45~55분쉬고 질문 정리모르는 단어 두 개만 고르게 해요.
55~80분한 줄 변경 → 결과 비교가격·인원·조건·문장을 한 번에 하나씩 바꿔요.
80~105분직업 프로젝트에 적용상담 서비스 또는 뷰티 메뉴에 같은 개념을 적용해요.
105~115분책 덮고 미니 과제이미 푼 문제와 숫자·이름이 다른 문제를 줘요.
115~120분설명과 숙제본인 말로 핵심 한 문장, 다음 복습 시간 정하기.

변수 수업의 실제 대화 예

선생님 질문기대할 행동
remaining = 3에서 어떤 이름과 값이 생겼나요?종이에 remaining → 3을 씁니다.
remaining = remaining - 1에서 먼저 읽는 쪽은?오른쪽 remaining의 현재 값 3을 가리킵니다.
계산 후 왼쪽에는 무엇을 넣나요?2라고 쓰고 이전 3을 지웁니다.
같은 줄을 한 번 더 실행하면?현재 2에서 1을 빼 1이 된다고 예상합니다.
왜 남은 자리에 const/val을 쓰지 않았을까요?값을 다시 대입해야 해서 let/var를 썼다고 설명합니다.

함수·클래스에서 멈췄을 때

  1. 함수 정의 부분에 큰 테두리를 그리고, 호출 부분에는 화살표를 그리게 하세요. 함수를 “실행할 절차에 붙인 이름”이라고 다시 읽어요.
  2. 매개변수 자리에 실제 인수 30000과 2를 써 보고 계산 결과를 return 화살표로 호출 위치에 돌려 보냅니다.
  3. 클래스 정의 한 개와 객체 생성 두 개를 나란히 놓고 각 객체의 name·price가 다르다는 것을 표로 확인합니다.
  4. 새 용어를 더하기 전에 같은 코드에서 변수·함수·클래스를 서로 구별할 수 있는지 확인해요.

새 함수 수업에서 던질 질문

“정의만 남기면 무엇이 출력될까요?” → “함수에 이름을 넘기면 어디로 들어갈까요?” → “return 값을 받은 변수는 무엇일까요?” → “함수 자체를 전달한 줄과 호출한 줄은 어디인가요?”를 순서대로 물어보세요.

학습자가 용어를 외우지 못해도 입력값과 실행 순서를 말할 수 있으면 출발할 수 있어요. 반대로 용어를 말해도 호출 결과를 예측하지 못하면 실행 추적을 더 연습합니다.

따라 치는 데 성공했지만 숫자를 바꾸면 못 한다면 무엇을 해야 하나요?

확인 답안과 이유

새 진도 대신 값을 바꿔 추적하는 짧은 문제를 반복해요. 한 번에 바꾸는 부분을 하나로 줄이고 실행 전 예측을 받습니다.

혼자 해 보는 과제

각 수업에 예측 질문 두 개, 일부 변경 문제 한 개, 책을 덮는 문제 한 개를 준비하세요.

선생님 수업 메모

LESSON 04

4장. 프로젝트 범위와 평가 기준

이 장을 마치면

필수 기능과 확장을 구분해 끝까지 완성해요.

상담사에게는 “문의 접수와 예약 확정이 어떻게 다른가”, 스타일리스트에게는 “같은 이름의 스타일을 어떻게 구별할까”처럼 익숙한 업무 질문을 쓰세요. 이 수업의 성공은 화면의 화려함보다 흐름을 이해하고 작은 변경을 혼자 할 수 있는지로 평가합니다.

평가 항목0점1점2점
기초 식별변수·함수·클래스를 못 찾음힌트로 구별실제 코드에서 위치와 역할 설명
동작 구현핵심 흐름 미완료복사 예제는 동작새 작은 요구를 혼자 수정
검사와 오류정상 입력만 실행실패 한 종류 검사빈 상태·경계·오류 원인을 설명
사용성작은 화면에서 사용 어려움주요 기능 사용 가능키보드/큰 글자·안내 문구도 확인
설명코드를 읽기 어려움흐름 일부 설명입력→처리→출력과 저장 범위 설명

총 10점 중 7점 이상, 핵심 흐름 동작, 기초 식별·검사 항목이 0점이 아니면 다음 과정으로 넘어가는 것을 권합니다. 이는 성적이 아니라 다음 복습을 정하기 위한 기준입니다. 부족한 항목은 해당 장을 짧게 다시 연습해요.

프로젝트필수확장 선택
상담 웹가상 소개·서비스·입력 라벨·공백 검사·희망 목록·삭제·폰 대응·실제 전송 아님 안내소개 사진, 브라우저에 가상 시간 저장, 정적 호스팅
뷰티 앱스타일 3개·고유 id·검색·빈 결과·찜·찜 필터·선택 상세·초기화사진, 메뉴 추가 입력, DataStore 장기 저장(후속)

LESSON 05

5장. 숙제, 질문과 막힘을 다루기

6장. 파일 사용과 검증 범위

이 장을 마치면

읽기·실행·인쇄·완료 표시의 차이를 알고 자료를 배포해요.

두 교재는 브라우저에서 여는 정적 HTML입니다. 서버를 설치하지 않아도 읽을 수 있어요. 웹 예제 실행은 외부 서비스를 호출하지 않는 격리된 미리보기이고, 앱 1~5장은 XML을 먼저 다루며, 6장 이후의 Kotlin 문법 예제만 Playground에서 실행합니다. 안드로이드 앱 예제는 Android Studio와 SDK가 필요합니다.

파일사용법
index.html전체 자료의 시작 화면
01-프론트엔드-입문-교재.html상담사 트랙. HTML·JS 연습장 포함
02-안드로이드-입문-교재.html스타일리스트 트랙. XML 화면·Kotlin 동작과 해설
03-참고-교재-비교.html책 10권·공개 학습 자료 비교와 설계 근거
examples/web/counseling.html독립 실행되는 완성 상담 웹
examples/web/starter.html웹 문서 기본 뼈대
examples/android/MainActivity.ktXML Views 템플릿에 넣는 전체 소스. 프로젝트 전체 ZIP은 아님
검증-기록.txt실제 자동 점검 범위와 아직 필요한 기기 검증 기록
  1. ZIP을 풀고 index.html을 브라우저로 여세요. 파일을 같은 폴더 구조로 유지하면 문서 사이 링크가 작동합니다.
  2. 웹 연습장의 실행 버튼은 누를 때마다 독립 실행돼요. 무한 반복 코드나 외부에서 가져온 불명 코드는 넣지 마세요.
  3. 인쇄/PDF 버튼을 누르면 해답 접힘이 펼쳐지고 코드 편집칸은 인쇄용 코드로 바뀝니다. 인쇄 후에는 원래 접힘 상태로 돌아와요.
  4. 장 완료는 현재 브라우저 저장 공간에 기록되며 파일을 다른 위치로 옮기면 이어지지 않을 수 있어요. 학습 기록 원본은 별도 일지로 남기세요.

안드로이드 예제에는 activity_main.xml과 MainActivity.kt를 함께 제공하며 장별 폴더도 들어 있습니다. 두 파일은 같은 예제 폴더에서 가져오세요.
